# Governance

The project is hosted by technicalzx and maintained by @AbuHurairh. Historical contributor and copyright attribution is retained. Contributors may propose issues, documentation changes, tests, fixes, and integrations through pull requests. Maintainer approval is required for merge and release.

Security-sensitive changes need explicit review of the threat model, dependency implications, tests and user permissions. Large changes should start with a proposal explaining scope and alternatives. Decisions should be recorded in an issue or architecture document without disclosing private investigation data.

The owner manages repository access, review enforcement, security reporting and releases. Use MFA, least privilege, separate reviews where possible, and periodic access review. Recruiting a second independent maintainer and establishing succession are open tasks. No unverified governance setting is represented as enabled merely because it appears in documentation.
